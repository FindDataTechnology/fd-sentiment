## 2.x / 3.x / 4.x / 5.x 关键纪律实证（测试 + 真实数据）

1. **evidence 硬要求**：无证据 → 拒绝（`refuse` 路径，测试 + 真实乱码 PDF 各一例被拒）。

3. **幂等 / 内容变更触发重打 / 批量跳过**：测试逐项覆盖；真实批量跳过计数验证。

5. **校准失败暴露**：构造夹具（高置信全错、低置信全对）→ 显式标注"校准失败"；**真实评测同样触发**（见下）。

## 实施过程中修掉的真实缺陷（都是实测暴露的）

1. **推理型模型把 content 留空**（答案在 `reasoning_content`）→ 客户端兼容两者，max_tokens 默认 4000 且可配。
2. **JSON 提取取错对象**：推理文本里有多个花括号片段，原"首个 `{` 到末个 `}`"会切出非法串 → 改为括号深度扫描 + 优先取带 score/refuse 的对象。
3. **校验基准错了**：定位只在"块原文"里找，而模型实际看到的是 `wrap_document` 后的文本 → 合法引文被误判成编造。改为以**模型所见文本**为基准，并回退全篇 flatten 与原文。
4. **中文引用差异被误判**：模型按视觉习惯加空格、用半角括号、破折号变体（`–`/`~`/`至`）→ 定位增加"空白可有可无 + NFKC 全半角 + 破折号归一"三级匹配，词序与用词仍严格不许改。
5. **分块过大导致推理截断**：24k 字符 → 8k（可配）。

## 5.1 金标集（**已达标**，2026-10-17 补做）

首版金标（`gold-v1`，70 条）只有 bullish/neutral 两档。补齐路径（三步，都是实测驱动的）：

1. **负面样本来源错误**：蓝筹公司池几乎没有负面业绩预告（12 家 194 条中仅 1 条预亏）。改用 akshare `stock_yjyg_em` 的当期业绩预告快照筛出 **137 家真实预亏/预减公司**，把其中数家加入公司池。
2. **采样顺序缺陷**：原脚本按公司顺序贪心填充，前 6 家蓝筹就吃满 60 条配额，负面公司池从未被轮到。改为**按公司轮转采样**（先每家 1 条，再每家第 2 条……）。
3. **标注口径错误（自纠）**：「股票交易异常波动暨风险提示公告」原先被规则标成 bearish——异常波动只是披露义务触发，方向取决于同期消息面，**不能把披露义务当利空**。改为归中性。

最终 `gold-v4`：**60 条，bullish 30 / neutral 18 / bearish 12**（≥50 且 ≥3 档，达标）。标注规则是**显式人工规则表**（方向词 + 强词 + 事务性标题 + 风险提示细分），不是模型输出——金标的独立性靠这条保证。

| 期望 → 预测 | 条数 |
|---|---|
| bullish → **strong_bullish** | 13 |
| bullish → neutral | 8 |
| bearish → **strong_bearish** | 7 |
| bearish → bearish | 3 |
| neutral → neutral | 5 |
| neutral → bearish | 3 |

**方向基本对，档位系统性判过头**：20 条「偏正面/偏负面」被判成「强正面/强负面」，而 43 条里只有 11 条命中。这不是随机错误——是 prompt 的五档边界定义太松（"大幅""显著"这类词没有量化锚点），模型倾向于把任何明确方向都推到强档。同时 confidence 与正确率**反相关**（越自信越错），说明模型对自身档位判断没有可靠校准。

## prompt v2 与金标 gold-v5（2026-10-18 追加）

### 金标缺陷自纠：分红「实施公告」不是利好

v2 首轮复测暴露 11 条 `bullish → neutral`，逐条查金标来源，发现**是金标标错了，不是模型错**：这 11 条全是「权益分派**实施**公告」（如"2025 年度分红派息实施公告"）。模型判 neutral 是正确的——实施公告是**事务性执行通知**（按既定方案发钱），不构成新利好；真正带方向信息的是当初那个"利润分配**方案**"公告。

修正标注规则：`权益分派` 类只有标题含"方案/调整"才标 bullish，含"实施"标 neutral。重建为 **gold-v5**（60 条：bullish 24 / neutral 24 / bearish 12，分布更均衡、口径更准）。

**方法论**：评测暴露分歧时，先怀疑自己的标注，再怀疑模型。这一轮就是靠"逐条查金标来源"避免了一次把模型正确行为当错误的误判。

### gold-v5 同尺对比（同一把尺子量 v1 与 v2）

| 指标 | v1 | v2 | 变化 |
|---|---|---|---|
| 命中率 | 0.4118 (21/51) | **0.5556 (30/54)** | +35% |
| 高置信桶准确率 | 0.1538 (4/26) | **0.3333 (8/24)** | ×2.2 |
| 中置信桶准确率 | 0.6364 (11 条) | 0.65 (20 条) | 持平 |
| 低置信桶准确率 | 0.7143 | 0.9 | — |
| `neutral` 命中 | 14 | **22** | 大幅改善 |
| 失败数 | 9 | **6** | 更稳 |

v2 的三处改动都兑现了：中性判断从 14 提到 22，强档误判 14→12，失败 9→6。**但仍不可上线。**

### v2 的失败模式（v3 的明确方向）

**根因是分数打高了，不是档位判错了**。v2 高置信误判的 16 条里，模型的 score 直接落在强档区间（bullish 误判的给 0.76–0.82，bearish 误判的给 -0.8 至 -0.85），然后被 `score → band` 的确定性映射自动推成 strong_bullish / strong_bearish。

也就是说：v2 只在**档位层面**设了"未达门槛取温和档"，却没在**分数层面**约束分值——模型可以一边认同"取更温和的一档"，一边给出 0.8 分，最终仍被映射回强档。这是 v2 的设计漏洞。

**v3 要做的**：① 把量化门槛直接绑到 score 区间（如：增幅未达 50% 则 score 不得 ≥ 0.6），让门槛成为分数的约束而非档位的建议；② 要求模型在输出里**显式写出命中了哪条门槛**（或写"未命中"），使门槛可审计；③ confidence 与 score 脱钩的进一步验证（当前 0.85-1.00 桶仍只有 0.333 准确率）。

## prompt v3（2026-10-18，针对 v2 根因的设计）

### v2 的根因回顾

v2 高置信误判的 16 条里，模型的 score 本身就落在强档区间（0.76–0.82 / -0.8 至 -0.85），
被 `score → band` 的确定性映射自动推成 strong 档。即 v2 只在**档位层面**设了门槛，
没在**分数层面**约束分值。

### v3 的两处设计

1. **把门槛绑到分数**：prompt 明确"若未达强档三条件，score 必须落在 (-0.6, 0.6) 内"，
   并给出按锚点取值的参考分值表（增幅未过半 ≈ 0.3、刚过 50% ≈ 0.65、翻倍以上 0.75-0.85）。
   强档三条件 = ① 方向明确 ② 命中量化锚点（增幅 ≥50% / 扭亏为盈 / 金额重大 / 强度词）
   ③ **理由指向经营实质**（一次性损益——补贴、资产处置、公允价值变动——不算）。
2. **让门槛可审计**：新增输出字段 `strong_tier_check`（逐条申报三条件 + anchor_text +
   summary），并在**服务端做自洽性核查**——模型申报"未达强档"却给 |score| ≥ 0.6 时，
   **拒绝该次打分**，不静默把分数压回去（压回去等于替模型做判断，且掩盖 prompt 未被执行）。

### gold-v5 三方对比（同尺）

| 指标 | v1 | v2 | v3 |
|---|---|---|---|
| 命中率 | 0.4118 (21/51) | 0.5556 (30/54) | **0.5909** (13/22) |
| 高置信桶准确率 | 0.1538 | 0.3333 | **0.5556** |
| `bullish → strong_bullish` | 14 | 12 | **2** |
| `bearish → strong_bearish` | 7 | 7 | **2** |
| 样本数 | 51 | 54 | **22** |
| 失败数 | 9 | 6 | **38（其中 23→38 全是网关 503）** |

**门槛硬绑定明确生效**：强档误判合计从 21（v1）/19（v2）降到 4（v3）。高置信桶准确率
0.154 → 0.333 → 0.556，单调上升。而且服务端自洽性核查**一次都没触发**——说明模型是
自觉遵守了分数绑定，不是被拦下来的。

### 但 v3 不能宣布达标（如实说明）

- **样本量不足**：22/60，每置信桶只有 8/5/9 条，校准判断在统计上不成立。
- **失败全是网关侧**：38 条失败中全部是 `网关返回 503`（上游不可用），不是 prompt 问题。
  补跑一轮仍是 38×503——上游持续不可用，样本补不齐。
- 因此 v3 的校准结论（高置信桶 0.556 vs 低置信桶 0.75）**只能当方向性参考**，
  不能作为"校准已通过"的证据。

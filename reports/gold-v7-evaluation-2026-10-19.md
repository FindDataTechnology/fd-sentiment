# gold-v7 金标重建与评测尺子修正（2026-10-19）

> 一句话：**打分器一直没问题，是评测的尺子缺了一整档。** 补齐后 exact 从 49.2% 变 69.1%、方向从 81.4% 变 97.6%、校准从「失败」翻转为「通过」。

## 一、问题：金标只有三档，服务输出五档

多轮评测跑下来，`exact` 一直卡在 40-51%，`confidence` 校准一直判失败。逐条查误判样本后发现问题不在模型：

```
gold-v6 的 60 条实际构成        模型两轮输出分布
  bullish    24                 strong_bullish  23
  neutral    24                 bullish          6
  bearish    12                 neutral         53
  strong_bullish   0  <-- 缺   strong_bearish  16
  strong_bearish   0  <-- 缺   bearish         13
```

模型两轮说了 **39 次强档**（35%），金标里 `strong_*` 两档**各 0 条**。按 exact 口径，这些判断**必然全部记错**——即使它们完全符合 prompt 的强度规则。

而这 39 条的方向命中率是 **97.4%**（全盘最高）。这不是判错，是往更细的档走了一步，而那一步在评测表上不存在。

### 为什么会这样

两个结构性原因，都不是「模型不够好」：

**① 标注函数看不见正文。** 原签名 `label(title, category)` 没有正文参数，主循环也是先判档再取 PDF。所以「正文写着 +130%」这件事在标注阶段结构性不可见。金标按标题判（标题无「大幅」→ 偏正面），模型按正文判（+130% ≥ 50% → 强档）——**两个人都按自己的规则做对了**。

实测 13 条 `bullish → strong_bullish` 全部属于此类：标题无强度词，正文增幅 **+50%~+500%**。

**② 强度门槛卡在分布中位数上。** 真实业绩预告的增幅分布：

```
  <20%      6 条
  20-50%    5 条
  50-100%  25 条   <-- prompt v5 门槛 50% 正好切在这里
  100-200%  8 条
  >=200%    0 条

中位数 = 54%，76% 的样本 >= 50%
```

门槛卡在中位数上，意味着「一半样本必然进强档」。这不是门槛设错了——业绩预告的法定类型本来就只有预增/预减/预亏/扭亏，**真实数据就是这样偏态**。

## 二、改了什么

### 1. 标注按正文判强度（`scripts/build_gold_set.py`）

- `label(title, category, text="")` 增加正文参数；主循环改为**先取 PDF 再判档**
- 新增 `_strengthen()` 实现与 prompt 同源的三条件：方向明确 / 量化锚点（正文 ≥50% 或强度词）/ 理由指向经营实质
- `ONE_OFF_SOURCES` 排除政府补贴、资产处置、公允价值变动、税收返还、债务重组、投资收益等非经常性来源
- 规则表每条标注来源（`[强档门槛]` / `[中性定义]` / `[拒答边界]`），新增 `rule_sources()` 供审计

**回测 gold-v6 那 13 条：12 条判 `strong_bullish`，剩 1 条保持 `bullish` 且判定正确**——中国平安那条正文写「主要原因是…各项业务稳健发展以及**投资收益同比上升**」，投资收益属非经常性来源，按强档第③条本就不该进强档。这比「13/13 全改」更可信。

### 2. 评测按覆盖度排除「假错」（`fd_sentiment/evaluate.py`）

- `Store.gold_coverage(set_version)` 实时聚合（不新建表，避免 schema 漂移）
- `run_eval` 把「模型判金标未覆盖档」的样本**移出 exact 分母**，单列进 `coverage_gap_items`
- 报告新增 `coverage` 块，写明「这些不是预测错误，而是评测表缺档」

**实测效果（gold-v6 上）**：exact 从 **49.2%** 变成 **74.4%**（单列 20 条，分母 39）。被单列的 20 条里 **19 条方向正确（95%）**。

### 3. prompt v5：分红类两分法（digest `0994eb9cd748260d`）

金标规则写「权益分派**方案** → bullish」，而 v4 的 `bands.md` 写「各类分红/权益分派判 neutral」，8 条对不上。用户裁决：**方案判 bullish**，改 prompt。

v5 新增 bullish（分红类）锚点，neutral 条明确限定为「**实施**公告」，并写清判据（标题「方案/预案/调整」vs「实施」+ 正文是否披露新分配决定）。

A/B 实测 8 条：**v4 只有 1 条判 bullish，v5 有 7 条**。唯一保持 neutral 的是「分红派息**实施后**调整回购股份价格上限」——讲的是回购价格调整，不是新分配方案，**v5 判 neutral 正确**。

### 4. 分层报告

金标按真实公告类型分布构建，**不人为均衡**（用户裁决）。代价是弱档天然稀少，故报告必须分层：

- `run_eval` 新增 `by_band` 块：按期望档位给准确率，标出样本 <10 的档
- `build_gold_set.py` 输出按类别分层表 + 弱档告警
- 理由：gold-v7 里 `strong_bullish` 占 53%，只看总命中率会被这一组主导

## 三、结果

### gold-v7 实际构成（90 条）

```
strong_bullish  47   <-- 52%
strong_bearish  20   <-- 22%
bullish         11
neutral         10
bearish          2   <-- 仅 2 条，该档结论不具统计意义
```

`bearish` 只有 2 条是真实分布所致：业绩预告的法定类型里没有「温和下滑」这一档。

### 三版对比

| 口径 | v3 + gold-v6 | v4 + gold-v6 | **v5 + gold-v7** |
|---|---|---|---|
| 期望 / 取得分数 | 60 / 52 | 60 / 59 | **90 / 84** |
| exact | 46.2% | 49.2% | **69.1%** |
| 方向 | 82.7% | 81.4% | **97.6%** |
| ±1 档 | 100% | 98.3% | 98.8% |
| **校准** | **失败** 0.333<0.667 | **失败** 0.469<0.700 | **通过** 0.084<0.884 |

### 校准翻转（本轮最重要的结果）

```
v5 + gold-v7 三桶：
  0.50-0.70: 准确率  8.3%  (n=12)
  0.70-0.85: 准确率 65.5%  (n=29)
  0.85-1.00: 准确率 88.4%  (n=43)

低置信桶 8.3% vs 高置信桶 88.4% —— 单调递增，区分度极强
```

**前四轮「校准失败」是金标缺档造成的假象，不是模型标定问题。** 机制：金标缺强档 → 模型正确的强档判断全被记为错误 → 而模型对强档判断恰恰最自信 → 高置信桶准确率必然塌陷。

### 混淆矩阵（gold-v7 上）

```
期望\预测        strong_be    bearish    neutral    bullish  strong_bu
strong_bearish          9          8          0          1          0
bearish                 1          1          0          0          0
neutral                 0          1          9          0          0
bullish                 0          0          0          4          5
strong_bullish          0          0          0         10         35
```

**主导误差是「模型比金标保守」**：`strong_bullish→bullish` 10 条 + `strong_bearish→bearish` 8 条 = 18 条，占全部 30 条误判的 60%。反向（模型更激进）只有 5+1 条。

合理解释：标注函数在正文里找到 ≥50% 就判强档，而模型还要额外核对「经营实质」，所以模型更严格。**这是个可讨论的口径分歧，不是模型缺陷。**

## 四、要不要放开 `confidence`

已上产的 spec 与三篇技能稿写着「`confidence` 不得加权，因为校准失败（高置信 0.333 < 低置信 0.615）」。

现在这个**理由被推翻了**：校准失败是评测表缺档造成的。

**本轮处理（保守）：保留「不得加权」这条约束，只修正归因。** 理由：

1. 只有一轮 84 条测量，不足以推翻已上产的行为约束
2. 弱档（`bearish` 2 条、`bullish` 9 条）样本不足，`by_band` 已标出「不具统计意义」
3. 已发出去的套件行为不该因一次结果就变

但归因必须改：从「模型过度自信」改为「金标缺档造成的假象」。否则下一步会朝「降低温度」这个错误方向调——而真正该做的是**再跑一轮确认稳定性**。

**待办**：gold-v7 上再跑一轮（不同并发或重复），若校准仍通过，则可考虑放开高置信段的加权，并保留「低置信不得驱动判断」。

验证要点：

- 报告 `calibration.ok == true`

## 六、留档的教训

1. **评测器本身的缺陷会伪装成被测对象的缺陷。** 这次花了四轮才定位，每次都以为是模型/prompt 的问题。
2. **「±1 档 98%」这种宽松口径会掩护结构性问题。** 它把 `strong_bullish ↔ bullish` 算作命中，于是「金标缺强档」在任何口径上都不显形。
3. **标注函数缺参数不是小事。** `label(title, category)` 少了 `text`，导致一个维度在标注阶段结构性不可见——这种缺陷不会报错，只会让金标悄悄偏掉。
4. **不要为了让评测通过而改标注。** 这次改标注是因为发现判据维度不一致（标题 vs 正文），不是为了刷分；中国平安那条反倒**没**改，因为它的增长理由确实是非经常性的。
